## 1. 目标与架构

- 在服务器新增一个独立的 Python 服务（FastAPI + uvicorn），提供 Web 版取号器（页面 + API）。
- 数据存服务器 SQLite（`data/numbering.db`），多台电脑共享同一编号库，编号分配在服务端原子完成。
- 推荐以 **systemd 服务 + Python venv** 方式部署（不依赖 Docker，不影响现有容器）；如需与现有环境一致也可改用 Docker 容器（另行预案）。
- 服务监听 `127.0.0.1:8001`（仅本机），由 OpenResty 反代对外暴露路径 `/numbering/`（与现有 `/blog/` 反代方式一致）。

## 2. 服务器目录规划

```text
~/numbering-app/
├── app/            # Web 后端源码（app/main.py 等）
├── core/           # 桌面版核心逻辑（creo编号器/core，编号规则复用）
├── web/dist/       # 前端构建产物（React 静态文件）
├── requirements.txt
└── data/           # SQLite 数据库（运行时生成，需可写）
```

## 3. 部署步骤（分步确认）

### 步骤 0：备份（必须）
- 备份 OpenResty 反代配置：`sudo cp /usr/local/openresty/nginx/conf/nginx.conf ~/nginx.conf.bak.$(date +%F)`
- 记录现有容器状态：`sudo docker ps` 输出保存到 `~/container-snapshot.txt`（只读，不重启任何容器）

### 步骤 1：上传代码
- 本地打包 `creo编号器/core` + `creo编号器-web`（app、web/dist、requirements.txt）上传到 `~/numbering-app/`
- 前端已在本地 `npm run build`，上传构建产物即可，服务器无需 Node

### 步骤 2：创建 venv 并安装依赖
```bash
cd ~/numbering-app
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
```

### 步骤 3：配置 systemd 服务
- 新建 `~/numbering-app/numbering.service`，内容要点：
  - `ExecStart=/home/ubuntu/numbering-app/venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8001`
  - `WorkingDirectory=/home/ubuntu/numbering-app`
  - `Restart=on-failure`
  - 环境变量 `DATA_DIR`（可选，数据库目录可配置）
- `sudo ln -s ~/numbering-app/numbering.service /etc/systemd/system/` 后
  `sudo systemctl daemon-reload && sudo systemctl enable numbering`

### 步骤 4：启动与健康检查（先本机验证，不加反代）
```bash
sudo systemctl start numbering
curl -s http://127.0.0.1:8001/api/projects   # 期望返回 []
curl -s http://127.0.0.1:8001/               # 期望返回前端页面
```
确认无误后再进入下一步；失败则回滚（见第 5 节）。

### 步骤 5：OpenResty 反代（可选，需再次确认）
- 在 OpenResty 配置中新增 `location /numbering/ { proxy_pass http://127.0.0.1:8001/; ... }`
  （路径与前端资源引用需保持一致，构建时如用相对路径则无冲突）
- `sudo /usr/local/openresty/nginx/sbin/nginx -t` 校验配置
- `sudo /usr/local/openresty/nginx/sbin/nginx -s reload`（仅重载，不重启）

### 步骤 6：线上验证
- 浏览器访问 `http://62.234.0.69/numbering/`（或域名对应路径）
- 新建项目 / 添加组件零件 / 导入桌面版 JSON，核对编号规则

## 4. 安全与多人预留
- 单人使用阶段**无登录**；若直接暴露公网，建议先做访问控制（内网使用 / IP 白名单 / 基础口令）。
- 多人阶段预留：`nodes` 表已含时间字段，后续可加 `users` 表与登录（小改动）。
- 编号分配在 SQLite `BEGIN IMMEDIATE` 事务中完成，天然防并发冲突。

## 5. 回滚方案
- 服务异常：`sudo systemctl stop numbering && sudo systemctl disable numbering`
- 反代异常：恢复备份 `sudo cp ~/nginx.conf.bak.* /usr/local/openresty/nginx/conf/nginx.conf` 后 `nginx -t && nginx -s reload`
- 数据回滚：`data/numbering.db` 建议每日备份（cron 复制到 `~/backups/`）

## 6. 不影响现有服务
- 本预案全程不修改博客/门户容器、不重启 Docker；
- 新增端口 8001 仅监听本机，OpenResty 反代前对外不可达。
